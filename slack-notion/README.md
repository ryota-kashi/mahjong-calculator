# Slack → Notion タスク追加

Slackのメッセージの […] メニューからNotionのデータベースを選ぶと、そのメッセージが
データベースのアイテム（タスク）として追加されるSlackアプリです。
Google Apps Script（GAS）のウェブアプリとして動きます。

## できること

- **利用者ごとに、よく使うNotionデータベースを事前登録できる**
  - ⚡ メニュー →「Notion DBの設定」で、共有済みのデータベースから複数選んで登録
  - 登録は**個人単位**。ほかの人の登録内容は見えないし、影響もしない
  - **登録していない人には候補が一切表示されず**、登録への案内だけが出る
- メッセージの […] → 「Notionに追加」で、**自分が登録したデータベースだけ**が候補に出る
  - 登録が1件だけなら最初から選択済みになる
- **AI（Gemini）が本文からタスクの中身を読み取る**
  - タスク名: 挨拶や飾りを落とし、何をすべきかが分かる短い名前にする
  - 期限: 「明日まで」「来週金曜」「9/15締切」などを投稿日基準で `YYYY-MM-DD` に解決する
  - 担当者: 名指しされた人を選ぶ。いなければタスクを追加した人
  - 優先度: 「至急」「なるはや」などから、そのDBの選択肢の中で判断する
  - 読み取れないものは空のまま。推測では入れない
- **スレッド内のメッセージなら、会話全体を読んで判断する**
  - 返信を含めた流れからタスク名・期限・担当者を決める
  - Notionの本文にも会話全体が「名前: 発言」の形で入る
- 選んだデータベースにページが1件作られる
  - **タイトル列**: AIが付けたタスク名（失敗時は本文の最初の行）
  - **日付列**（あれば）: AIが読み取った期限
  - **people列**（あれば）: 担当者（SlackとNotionをメールアドレスで突き合わせる）
  - **select / status列**（あれば）: 優先度
  - **URL列**（あれば）: そのメッセージへのSlackリンク
  - **本文**: 期限・優先度・担当・Slackへのリンク・投稿者・チャンネル・投稿日時＋本文の引用
- 追加できたら、実行した本人にだけ見えるメッセージでNotionページのリンクを返す
- **完了通知の「修正する」ボタン**から、タスク名と期限をその場で直せる
  （AIが読み違えたときにSlackを離れずに直せる）
- **⚡ メニューの「自分のNotionタスク」で完了報告できる**
  - 登録したDBを横断して、自分が担当の未完了タスクを期限の近い順に一覧表示
  - 各行の［完了］を押すとNotionのステータスが完了になり、その行だけ完了表示に変わる
  - 作成直後の通知にも［完了にする］ボタンが付く

## 処理の流れ

```
【設定】⚡ メニュー →「Notion DBの設定」
   │  shortcut
   ▼
doPost ──▶ 共有済みDB一覧（キャッシュ）から複数選択させる
   │  view_submission
   ▼
doPost ──▶ スクリプトプロパティに「Uxxxx の登録DB」として保存

【利用】メッセージの […] →「Notionに追加」
   │  message_action
   ▼
doPost ── 検証 ──▶ 本人の登録DB ──┬─ 0件 ─▶ 登録を促す案内モーダル
   │                              └─ 1件以上 ─▶ 選択モーダル
   │  view_submission
   ▼
doPost ──▶ ジョブを預けて即座に応答（モーダルが閉じる）
   │        ＋「追加しています…」を通知
   │        ＋ 直後に走る使い捨てトリガーを作成
   ▼
runQueuedTasksNow（数秒後）
   ├─ スレッドなら conversations.replies で会話全体を取得
   ├─ Gemini でタスク名・期限・担当者・優先度を抽出
   ├─ Notion /v1/pages でページ作成
   └─▶ response_url で完了通知（「修正する」ボタン付き）

【修正】完了通知の「修正する」
   │  block_actions
   ▼
doPost ──▶ タスク名と期限を編集するモーダル
   │  view_submission
   ▼
doPost ──▶ Notion /v1/pages/{id} を更新（ここは速いのでその場で処理）

【完了報告】⚡ メニュー →「自分のNotionタスク」
   │  shortcut
   ▼
doPost ──▶ 読み込み中モーダルを開いて即応答（view_id を控えてジョブを預ける）
   ▼
runQueuedTasksNow（数秒後）
   └─▶ 登録DBを横断して未完了を検索 ──▶ views.update で一覧に差し替え
   │  ［完了］ボタン → block_actions
   ▼
doPost ──▶ Notion を完了にして、その行だけ views.update で書き換え
           （一覧の取り直しはしない）
```

Slackは3秒以内の応答を求めますが、AIの解析（1〜2秒）とNotionへの書き込みを
その中でやると間に合いません。そのため送信時はジョブを預けるだけにして、
直後に走る使い捨てトリガーで実際の作成を行います。
取りこぼしに備えて5分ごとの掃除トリガーも動かします。

`trigger_id` も発行から3秒で失効するため、モーダルを開く経路ではNotionを呼ばず、
1時間ごとのトリガーで更新したデータベース一覧のキャッシュだけを読みます。
利用者ごとの登録内容も、リクエストの最初に1回だけ読むスクリプトプロパティから引きます。

## 登録データの持ち方

スクリプトプロパティに `USER_DATABASES_<SlackユーザーID>` というキーで
`{"ids": ["<データベースID>", ...], "updatedAt": "..."}` を保存します。
Notion側で共有が外されたデータベースは、候補にも設定画面の初期選択にも出なくなります
（登録を消し回る必要はありません）。

## セットアップ

### 1. Notion側

1. https://www.notion.so/my-integrations で内部インテグレーションを作る
   - 権限は「コンテンツを読み取る」「コンテンツを挿入する」が必要
2. Internal Integration Token（`ntn_...`）を控える
3. 追加先にしたい**各データベース**のページを開き、`…` → 「接続」から作成した
   インテグレーションを追加する（共有していないデータベースは候補に出ません）

### 2. Gemini側

1. https://aistudio.google.com/apikey でAPIキーを発行する
2. キーを控える（スクリプトプロパティ `GEMINI_API_KEY` に入れます）

APIキーを設定しない場合、AIによる抽出は行われず、タスク名は本文の最初の行、
期限は空のままになります（そのままでも動きます）。

### 3. Apps Script側

付属のスクリプトを使う場合（プロジェクト作成とコード反映まで自動）:

```bash
bash slack-notion/setup.sh
```

事前に https://script.google.com/home/usersettings で
「Google Apps Script API」をオンにしておいてください。
Googleへのログインは途中でブラウザが開きます。

手で作る場合（claspを使わない場合）:

1. https://script.google.com で新規プロジェクトを作る
2. [`dist/Code.gs`](dist/Code.gs) の中身を**まるごと**「コード.gs」に貼り付ける
   （`src/*.gs` を1ファイルにまとめたものです。ファイルを分ける必要はありません）
3. プロジェクトの設定でタイムゾーンが「日本標準時」になっているか確認する
   （投稿日時の表示と「明日まで」の解決に使います）

`dist/Code.gs` は `src/` から自動生成しています。`src/` を直したら
`npm run build:slack-notion` で作り直してください（CIで一致を確認しています）。

### 4. スクリプトプロパティ

エディタの「プロジェクトの設定」→「スクリプト プロパティ」で設定します。

| キー | 必須 | 内容 |
| --- | --- | --- |
| `SLACK_BOT_TOKEN` | ✅ | Slackアプリの Bot User OAuth Token（`xoxb-...`） |
| `SLACK_VERIFICATION_TOKEN` | ✅ | Slackアプリの Basic Information → Verification Token |
| `NOTION_TOKEN` | ✅ | Notion の Internal Integration Token（`ntn_...`） |
| `GEMINI_API_KEY` | 推奨 | Google AI Studio のAPIキー。未設定ならAI抽出を行わない |
| `WEBHOOK_SECRET` | 推奨 | 任意の合言葉。Request URL に `?s=<合言葉>` として付ける |
| `GEMINI_MODEL` | 任意 | 使うモデル（既定 `gemini-2.5-flash`） |
| `GEMINI_THINKING_BUDGET` | 任意 | 思考トークン上限（既定 `0`＝思考なしで最速）。`-1` で指定自体を送らない |
| `NOTION_DATABASE_ALLOWLIST` | 任意 | **登録できる**データベースIDをカンマ区切りで指定（管理者が範囲を絞る用） |
| `NOTION_URL_PROPERTY` | 任意 | SlackリンクをNotionのどのURL列に入れるか（列名） |
| `NOTION_DUE_PROPERTY` | 任意 | 期限をNotionのどの日付列に入れるか（列名） |
| `NOTION_ASSIGNEE_PROPERTY` | 任意 | 担当者をどのpeople列に入れるか（列名） |
| `NOTION_PRIORITY_PROPERTY` | 任意 | 優先度をどのselect / status列に入れるか（列名） |
| `NOTION_DONE_PROPERTY` | 任意 | 完了状態を持つ列（select / status / checkbox の列名） |
| `NOTION_DONE_VALUE` | 任意 | 完了とみなす選択肢名（`NOTION_DONE_PROPERTY` と組で指定） |
| `NOTION_VERSION` | 任意 | Notion APIのバージョン（既定 `2022-06-28`） |

列名を指定しない場合は名前から自動で判定します。

| 用途 | 自動で選ばれる列 |
| --- | --- |
| Slackリンク | 名前に `slack` / `link` / `url` / `リンク` を含む **URL型** の列 |
| 期限 | 名前に `期限` / `締切` / `締め切り` / `due` / `deadline` を含む **日付型** の列。<br>無ければ `日付` / `実施日` / `予定日` / `Date` |
| 担当者 | 名前に `担当` / `assignee` / `owner` / `アサイン` / `responsible` を含む **people型** の列。<br>無くても people型の列がひとつだけならその列 |
| 優先度 | 名前に `優先` / `priority` / `重要度` を含む **select型 / status型** の列（選択肢があるもの） |
| 完了 | 名前に `ステータス` / `状態` / `status` / `進捗` を含む **status型 / select型** の列。<br>完了値は status型なら「完了」グループの選択肢、無ければ `完了` / `Done` / `終了` などの名前。<br>該当がなければ `完了` / `Done` / `済` という名前の **チェックボックス列** |

該当する列がなければ何も書き込みません。列名を明示した場合は、その名前の列が
あるときだけ書き込みます（勝手に別の列を埋めることはありません）。

### 5. ウェブアプリとしてデプロイ

「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」

- 次のユーザーとして実行: **自分**
- アクセスできるユーザー: **全員**

発行された `https://script.google.com/macros/s/.../exec` を控えます。
`WEBHOOK_SECRET` を設定した場合は末尾に `?s=<合言葉>` を付けたものがRequest URLです。

> コードを直したら「デプロイを管理」→ 鉛筆アイコン →「バージョン: 新バージョン」→
> 「デプロイ」まで行わないと `/exec` には反映されません。

### 6. Slackアプリ

1. https://api.slack.com/apps → 「Create New App」→「From an app manifest」
2. `slack-app-manifest.json` を貼り付ける
3. `settings.interactivity.request_url` を5で控えたURLに書き換える
4. 「Install to Workspace」でインストールし、Bot User OAuth Token を控える
   - スレッドを読むために、使うチャンネルで `/invite @Notionタスク追加` してください
     （botが参加していないチャンネルではスレッドを取得できず、選んだ1件だけで作成します）
5. Basic Information の Verification Token を控える
6. 4と5で控えた値をスクリプトプロパティに設定する

### 7. トリガーの設定

Apps Scriptエディタで `installTriggers` を1回実行します。次の2つが作られ、
その場でデータベース一覧の初回取得も走ります。

| トリガー | 間隔 | 役割 |
| --- | --- | --- |
| `refreshCaches` | 1時間 | データベース一覧とNotionメンバー一覧を取り直す |
| `sweepQueuedTasks` | 5分 | 取りこぼしたジョブを拾う保険 |

実際の作成処理は、送信のたびに作られる使い捨てトリガー（`runQueuedTasksNow`）が行います。

> このとき「トリガーの作成」と「外部サービスへの接続」の権限を求められます。
> 初回は必ずエディタから1回実行して承認してください。承認しないとウェブアプリ側で
> ジョブの処理トリガーを作れず、5分ごとの掃除トリガー頼みになります。

### 8. 利用者に登録してもらう

管理者側の作業はここまでです。あとは各利用者が ⚡ メニュー →「Notion DBの設定」から
自分の使うデータベースを登録します（次の「使い方」を参照）。

## 使い方

### 1. 追加先を登録する（利用者が各自で1回だけ）

メッセージ入力欄の ⚡（またはプラス）メニュー →「Notion DBの設定」→
よく使うデータベースを選んで「保存」。

未登録のままメッセージの […] から使おうとした場合も、案内モーダルの
「データベースを登録」ボタンからその場で登録できます。

### 2. メッセージをタスクにする

Slackのメッセージにマウスを乗せる → […] →「Notionに追加」
（初回は「その他のメッセージ ショートカット」の中にあります）。
自分が登録したデータベースが候補に出るので、選んで「追加」。
モーダルはすぐ閉じ、「追加しています…」の後、数秒後に完了メッセージが届きます。

登録内容はいつでも ⚡ メニュー →「Notion DBの設定」から変更できます。
すべての選択を外して保存すると登録解除になり、候補は表示されなくなります。

### 3. 完了を報告する

⚡ メニュー →「自分のNotionタスク」で、登録したDBを横断した未完了タスクが
期限の近い順に並びます。各行の［完了］を押すとNotionのステータスが完了になります。

作成直後であれば、完了通知に付く［完了にする］ボタンからも同じことができます。

一覧に出すには、追加先のDBに**担当者列（people型）と完了列の両方**が必要です
（どちらかが無いDBは一覧の対象外になり、その旨が下部に表示されます）。

## 手で実行できる関数

| 関数 | 用途 |
| --- | --- |
| `showSetupStatus` | どのプロパティが設定済みかを確認する（値は伏せて表示） |
| `refreshDatabaseCache` | データベース一覧を取り直し、検出した列をログに出す |
| `refreshNotionUserCache` | Notionのメンバー一覧を取り直す（担当者の突き合わせ用） |
| `refreshCaches` | 上の2つをまとめて実行する（1時間ごとのトリガーの中身） |
| `installTriggers` | 必要なトリガー（一覧更新・キューの掃除）を作る |
| `showQueue` | 未処理のジョブを確認する |
| `listUserRegistrations` | 誰がどのデータベースを登録しているか一覧する |
| `deleteUserRegistration` | 指定した利用者の登録を消す（退職者の整理など） |
| `clearCaches` | キャッシュを捨てる（データベースを共有した直後の確認用） |

## 既知の制約（Apps Scriptを選んだことによるもの）

- **署名検証ができない**
  Apps Script の `doPost` はリクエストヘッダーを読めないため、Slack推奨の
  `X-Slack-Signature` による検証ができません。代わりに、ペイロードに含まれる
  Verification Token（Slackでは非推奨扱い）と、Request URLに付けた `WEBHOOK_SECRET`
  の2つで照合しています。URLと合言葉が漏れない限りは第三者からの投入を防げますが、
  厳密な署名検証が要件になる場合はGAS以外の実行環境が必要です。
- **ウェブアプリのレスポンスは302リダイレクトを挟む**
  Apps Script は `/exec` へのPOSTに対して `googleusercontent.com` へのリダイレクトを
  返します。Slackはこれを追跡するため通常は問題になりませんが、画面の描画は
  レスポンス本文ではなく `views.open` API で行う作りにして、影響を受けにくくしています。
- **3秒制限とコールドスタート**
  Slackは `trigger_id` を3秒で失効させます。データベース一覧をキャッシュから読む設計に
  していますが、久しぶりの実行でGASの起動が遅いと稀に間に合わずモーダルが開かないこと
  があります。その場合はもう一度 […] から実行してください（2回目以降は速くなります）。
- **追加は非同期。完了まで数秒かかる**
  AIの解析とNotionへの書き込みは3秒に収まらないため、送信時はジョブを預けるだけにして、
  直後に走る使い捨てトリガーで作成します。GASの `after()` トリガーは通常は数秒で発火
  しますが、混み合っていると1分程度かかることがあります。さらに取りこぼした場合は
  5分ごとの掃除トリガーが拾います。
  進捗は「⏳ 追加しています…」→「✅ 追加しました」の2通で分かるようにしています。
- **失敗したジョブは再試行しない**
  同じ失敗を繰り返さないよう、取り出した時点でジョブを消します。失敗理由はSlackに
  通知されるので、必要ならもう一度 […] から実行してください。
- **AIの結果はそのまま使う**
  確認画面を挟まずに書き込まれます。読み違えたときは、完了通知の「修正する」ボタンから
  タスク名と期限を直せます（担当者と優先度はNotion側で直してください）。
  抽出できなかったときは本文の1行目がタスク名になり、ほかは空のままです。
- **一覧は最大5DB・25件まで**
  1回のモーダル表示でNotionを何度も引くため、見に行くのは登録の先頭5DB、
  表示は25件までにしています。それを超える場合は下部にその旨が出ます。
- **完了報告できるのは担当者列と完了列があるDBだけ**
  「自分のタスク」は担当者（people列）で絞り込むため、担当者列と完了列の
  両方があるDBだけが対象です。片方でも欠けるDBは一覧から除かれます。
- **担当者はメールアドレスで突き合わせる**
  Slackのメールアドレス（`users:read.email`）とNotionのメンバーのメールアドレスが
  一致した人だけを担当者に設定します。ゲストや外部の人など、Notionワークスペースに
  いない人は担当者になりません（その場合は空のままページが作られます）。
- **スレッド取得にはbotの参加が必要**
  `conversations.replies` は botが参加しているチャンネルしか読めません。
  参加していない場合や履歴スコープが足りない場合は、選んだ1件だけで作成します
  （エラーにはしません）。
- **本文はAIに送られる**
  抽出のため、メッセージ本文（スレッドの場合は会話全体。先頭6000文字まで）が
  Google の Gemini API に送信されます。社外に出せない内容を扱うチャンネルで使う場合は、
  `GEMINI_API_KEY` を設定しない運用（AI抽出なし）も選べます。
- **… メニューの項目自体は全員に見える**
  Slackの仕様上、メッセージショートカットを利用者ごとに出し分けることはできません。
  そのため「使っていない人に見せない」は、押した後の挙動で実現しています。
  未登録の人には候補を一切出さず（ほかの人の登録内容も見えません）、
  登録への案内だけを表示します。
- **登録できるのは100件まで**
  Slackのセレクトの上限です。共有済みのデータベースがそれを超える場合、
  設定画面には最近更新された100件を出します。`NOTION_DATABASE_ALLOWLIST` で
  登録できる範囲を管理者が絞れます。
- **スクリプトプロパティの容量**
  登録内容は1利用者につき1プロパティ（上限9KB／全体500KB）です。
  100件登録しても4KB程度なので通常は問題になりませんが、
  数百人規模で使う場合は全体の上限に注意してください。

## テスト

```bash
npm run test:slack-notion
```

`tests/slack-notion.test.mjs` が `src/*.gs` をNode上のVMに読み込み、GASのサービス
（`UrlFetchApp`・`ScriptApp`・`LockService` など）を差し替えて、検証・モーダル生成・
利用者ごとの分離・Geminiへのリクエスト内容と応答の扱い・キューの動き・Notionへの
リクエスト内容・エラー処理を確認します。実際のSlack/Notion/Geminiには接続しません。

## うまく動かないとき

| 症状 | 確認すること |
| --- | --- |
| ショートカットを押しても何も起きない | Apps Scriptの「実行数」ログにエラーが出ていないか。Request URLとデプロイ済みバージョンが最新か |
| 「追加先が未登録です」と出る | ⚡ メニュー →「Notion DBの設定」から登録する（利用者ごとの登録が必要です） |
| 設定画面に「選べるDBがありません」と出る | Notion側で各データベースをIntegrationに共有したか。`refreshDatabaseCache` を実行してログを見る |
| 共有したデータベースが設定画面に出ない | 一覧は1時間キャッシュ。`clearCaches` か `refreshDatabaseCache` を実行する。タイトル列のないデータベースは候補になりません |
| 登録したはずのDBが候補から消えた | Notion側で共有が外れていないか。設定画面を開くと現状の候補が確認できます |
| 「Notionへの追加に失敗しました」 | メッセージに出るNotionのエラー文を確認。必須の列がある（未入力を許さない）データベースは追加できません |
| 「追加しています…」のまま完了しない | `showQueue` で未処理のジョブを確認。トリガーの承認が済んでいない可能性があります（`installTriggers` をエディタから実行して承認する） |
| タスク名がAIっぽくない／本文の1行目のまま | `GEMINI_API_KEY` が設定されているか。実行ログにGeminiのエラーが出ていないか（クォータ超過など） |
| 期限が入らない | 追加先のデータベースに日付型の列があるか。列名が自動判定に引っかからない場合は `NOTION_DUE_PROPERTY` で明示する。本文に期限が書かれていない場合は空のままが正しい挙動です |
| 期限が意図しない列に入る | `NOTION_DUE_PROPERTY` で列名を明示する。指定するとその列以外には書き込みません |
| 担当者が入らない | 追加先にpeople型の列があるか。SlackとNotionでメールアドレスが一致しているか（`refreshNotionUserCache` のログで取得できているメンバーを確認）。`users:read.email` スコープを入れて再インストールしたか |
| スレッドが取り込まれない | そのチャンネルにbotを `/invite` したか。履歴スコープを入れて再インストールしたか。実行ログに `not_in_channel` や `missing_scope` が出ていないか |
| 優先度が入らない | 追加先にselect / status型の列があり、選択肢が定義されているか。列名が自動判定に引っかからない場合は `NOTION_PRIORITY_PROPERTY` で明示する |
| 「自分のタスク」に何も出ない | 追加先に担当者列と完了列の両方があるか。担当者が自分になっているか。SlackとNotionのメールアドレスが一致しているか |
| 完了にしても状態が変わらない | 完了列の自動判定が外れている可能性があります。`refreshDatabaseCache` のログで検出された列を確認し、違えば `NOTION_DONE_PROPERTY` と `NOTION_DONE_VALUE` で明示する |
| 何も起きずログに「Verification Token が一致しません」 | `SLACK_VERIFICATION_TOKEN` がSlackアプリの値と一致しているか |
